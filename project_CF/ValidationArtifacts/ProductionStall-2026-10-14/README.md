# 중복 시설의 생산·재료 공급 중단 수정

작업일: 2026-10-14

## 신고와 재현

채굴기·정제소·가공소를 중복 건설한 뒤 일부 시설이 재료를 받지 못하고 생산을 멈춘다는 신고를 조사했다. 정제소는 재료 2스택에서 멈춘다는 조건을 반영했다. 해당 게임의 저장 항목에서 조사할 저장본을 확보하지 못해 원본 저장을 변경하지 않고 독립된 시뮬레이션으로 재현했다.

전력·경로·저장 공간을 확보한 상태에서 같은 생산 시설 3개를 만들고, 창고에 재료가 16초 간격으로 2스택씩 들어오는 상황을 구성했다. 재료는 출발 창고에만 추가했으며 각 생산 시설의 입고는 실제 드론으로 수행했다. 수정 전 정제소는 철광석 2스택, 가공소는 철판 1스택에서 뒤에 지은 시설이 계속 기다렸고 생산 실적은 0이었다.

채굴기도 같은 철광석 채굴기를 추가한 뒤, 창고의 여유가 간헐적으로 2스택씩 생기는 상황을 재현했다. 먼저 건설한 채굴기만 출고되어 생산을 재개하고 뒤의 채굴기는 가득 찬 재고를 출고하지 못해 계속 멈췄다.

## 원인

FoundrySession.AddRequests()의 우선순위는 급한 생산 재료에 5점, 대기 시간에 최대 4점을 더한다. 대기 보너스는 3초마다 1점이므로 12초가 지나면 더 증가하지 않는다.

재료 공급 간격이 12초 이상이면 방금 전 공급을 받은 시설과 훨씬 오래 기다린 시설 모두 같은 최대 점수가 된다. 기존 DroneWorkPlanner는 점수가 같은 요청을 시설·자원 목록 순서대로 선택했다. 결과적으로 앞에 건설한 시설이 같은 재료를 반복해서 가져가고 뒤의 시설은 영구 대기할 수 있었다. 창고 입고 요청도 출발 채굴기가 달라도 같은 점수일 때 목록 앞의 채굴기를 반복 선택했다.

## 수정

- 기존 생산·시장·창고 작업 우선순위와 급한 재료·여유분 보충의 구분은 유지했다.
- 동점일 때 실제 대기 시간이 더 긴 운송 경로를 먼저 선택한다.
- 경로는 출발 시설·도착 시설·자원 조합으로 구분하고 혜성마다 따로 마지막 배정 시각을 기록한다.
- 철거한 시설의 배정 기록을 정리한다.
- 재료 생성량, 레시피, 비용, 생산 시간과 저장 버전은 변경하지 않았다.

주요 코드: Assets/CometFoundry/Scripts/Simulation/FoundrySession.cs, DroneWorkPlanner.cs, DroneHaulRequest.cs, FoundryExpansion.cs. 재현 테스트: Assets/CometFoundry/Tests/EditMode/FoundryProductionFairnessTests.cs.

검증은 열린 Unity 에디터를 유지하기 위해 별도 프로젝트 사본에서 수행했다. 원본과 검증 사본의 C# 파일 71개가 일치한다. 원본 플레이 진행 및 저장 항목은 수정하지 않았다.

Windows 정식 빌드 갱신에 성공했고, 1280×720에서 63개 검증 화면과 시뮬레이션 초기화를 실행해 런타임 오류 없이 정상 종료했다. [플레이 로그](player.log), [장면별 검사](player-layout.tsv)를 함께 보존했다.

## 적용

업데이트된 Builds/CometFoundry/CometFoundry.exe를 재실행하거나, Unity에서 스크립트 컴파일 후 플레이를 다시 시작하면 적용된다. 기존 저장 데이터 불러오기에서도 정상 재개를 검증했다. 지금까지의 플레이에서 원재료 고갈·전력 부족·막힌 통로·가득 찬 창고로 정지하는 정상 조건은 그대로 적용된다.
