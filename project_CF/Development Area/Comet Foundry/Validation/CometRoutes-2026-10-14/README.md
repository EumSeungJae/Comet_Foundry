# 드론 통로·혜성 생성 검증

Unity 6000.3.19f1. 별도 검증 프로젝트에서 검사했으며 원본과 사본의 C# 76개 파일 해시가 모두 일치했다. 사용자 저장 데이터는 사용하거나 덮어쓰지 않았다.

## 자동 검사

전체 110개 중 105개 통과. 신규 지형 검사 7개 등급 × 8개 크기(9~16) × 16개 시드 = 896개 조합 전부 통과했다.

- 활성 타일 수가 등급 비율을 반올림한 목표와 일치한다.
- 외곽 한 줄을 제외한 모든 내부 타일이 활성·통행 가능 상태다.
- 상하좌우 탐색으로 모든 활성 타일에 도달할 수 있다.

튜토리얼 전체 진행 검사도 통과했다. 새 설명 2개를 포함한 팝업이 노란 타깃을 가리지 않고 화면 안에 배치되며 설명 글이 팝업 내부에 들어간다. 기존 병렬 드론·생산·저장 테스트도 통과했다.

기존 실패 5개는 유지됐다: 생성기 시드 코드 테스트의 범위 예외, 시장 이벤트 소수점 오차, 시장 신뢰도 가격 기대값 2개, 의뢰 갱신 ID 기대값. 이번 수정으로 추가된 실패는 없다.

## 변경 규칙

| 등급 | 이전 활성 비율 | 신규 활성 비율 |
|---|---:|---:|
| S | 100% | 100% |
| A | 90% | 98% |
| B | 80% | 96% |
| C | 70% | 94% |
| D | 60% | 92% |
| E | 50% | 90% |
| F | 40% | 88% |

손상은 외곽에만 배치하고 내부를 보존한다. 손상 후보로 인해 남은 타일이 고립되면 해당 손상을 되돌린다. 크기·자원량·거리 규칙은 유지한다. 기존 저장의 지형은 변경하지 않으며 새로 생성되는 혜성부터 적용한다.

튜토리얼 7장에 ‘드론의 이동 · 빈 통로 확보’, ‘드론의 작업 · 회수부터 복귀까지’를 각각 별도 팝업으로 추가했다. 폭 1칸 이상의 빈 통로, 상하좌우 이동, 건물·손상 공간의 통행 불가, 회수·배송·복귀 경로와 대기 조건을 설명한다. 건설로 통로를 막는 경우까지 자동으로 방지하지는 않으므로 플레이어가 통로를 남겨야 한다.

## Windows 실행 확인

Windows 빌드 성공 후 실제 1280×720 게임 창에서 66개 화면을 촬영했다. 새 팝업 2개를 직접 확인했으며 타깃·팝업 배치 검사 전부 통과, 텍스트 넘침 경고 0개, 플레이어 예외 0개다. 최신 실행 파일은 `Builds/CometFoundry/CometFoundry.exe`다.
