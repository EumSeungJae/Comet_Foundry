# Comet Foundry | 코딩 스크립트 기술서

혜성의 자원을 채굴하고, 가공·조립·운송·판매로 산업망을 확장하는 2D 경영 시뮬레이션입니다. Unity 6000.3.19f1과 C#을 사용하며, 자원과 시설의 데이터 정의, 게임 상태, 화면 제어를 구분해 구성했습니다.

## 1. 스크립트 구성

| 구성 | 주요 스크립트 | 역할 |
|---|---|---|
| 공통 기능 | `Inventory`, `SimulationId` | 시설 재고·저장 용량과 객체 식별자 관리 |
| 콘텐츠 데이터 | `FoundryContent`, `ResourceDefinition`, `RecipeDefinition`, `FacilityDefinition` | 자원, 생산 재료·시간·비용, 시설 크기·기능 정의 |
| 게임 진행 | `FoundrySession` | 건설, 시간 진행, 생산과 물류를 연결하는 플레이 상태 관리 |
| 기능별 처리 | `PlacementSystem`, `FacilityInstance`, `PowerSystem`, `DroneLogisticsSystem`, `DroneWorkPlanner` | 시설 배치, 생산, 전력 계산, 드론 운송 및 작업 우선순위 처리 |
| 경영·확장·저장 | `FoundryExpansion`, `FoundryMissionsAndDemolition`, `FoundryPersistence` | 거래·혜성 확장·수송·미션·철거·저장 기능을 `FoundrySession`의 partial class로 분리 |
| 화면·입력 | `FoundryPlayableController`, `FoundryManagementUI` | 플레이 입력, 생산품 선택, 경영 정보 및 조작 화면 표시 |

## 2. 핵심 구현

**데이터 기반 생산 체계**  
16종 자원과 16종 레시피를 정의해 채굴부터 완제품 조립까지 연결했습니다. 시설은 지원하는 레시피를 선택해 생산하며, 재료·운영 자금·출력 저장 공간을 확인한 뒤 생산을 진행합니다. 콘텐츠 정의에는 ScriptableObject를 사용하고, 플레이용 데이터는 `FoundryContent`에서 생성합니다.

**조건을 반영하는 건설과 생산**  
건설 시 타일 점유, 시설 크기, 자원 노드와 건설 자금을 검사합니다. 채굴은 실제 매장량을 소모하며, 전력 부족이나 자원 고갈 등의 조건에 따라 생산이 중단됩니다. 시설별 재고를 두어 생산과 운송이 서로 영향을 주도록 구성했습니다.

**자동 물류와 경영 확장**  
드론 운송 요청은 출발 시설의 재고와 도착 시설의 여유 공간을 검사하고, 실행 가능한 요청 중 우선순위가 높은 작업을 선택합니다. 거래소 매매, 신규 혜성 탐사·확보, 혜성 간 수송을 통해 생산망을 확장할 수 있습니다.

**시간 진행과 상태 복원**  
화면 컨트롤러가 전달한 시간을 `FoundrySession.Advance()`에서 0.1초 단위로 처리해 여러 혜성의 시뮬레이션을 갱신합니다. 저장은 `JsonUtility`로 상태를 JSON으로 변환한 뒤 `PlayerPrefs`에 기록하며, 시설·재고·매장량·수송·미션 상태 등을 복원합니다. 불러오기에는 저장 버전 처리와 데이터 유효성 검사를 포함했습니다.

## 3. 실행 흐름

플레이어 입력 → 화면 컨트롤러 → `FoundrySession`의 조건 검사·상태 변경 → 생산·전력·물류 갱신 → 재고·자금·진행 상황 화면 표시

예를 들어 채굴한 철광석은 드론으로 운반되어 철괴로 제련되고, 철판·기어 등의 중간재를 거쳐 완제품 생산에 사용됩니다. 각 단계는 레시피와 시설 재고를 기준으로 연결됩니다.

## 4. 설계 포인트와 검증

화면과 시뮬레이션 로직을 구분하고, 콘텐츠 정의와 실행 중인 시설 상태를 분리했습니다. 이를 통해 같은 생산 처리 코드에 다른 레시피를 적용할 수 있으며, 화면 조작 없이도 주요 시뮬레이션 기능을 EditMode 테스트로 검증할 수 있습니다.

생산·건설·물류·시장·저장 복원 등에 대한 테스트 코드가 포함되어 있습니다. 2026-10-08 검증 기록에서는 신규 생산 테스트 8개 통과와 Windows 실행 파일 빌드 성공을 확인했습니다. 같은 기록의 초기 전체 테스트는 55개 중 50개 통과, 5개 실패이며, 이번 기술서 작성 과정에서는 테스트를 새로 실행하지 않았습니다.
