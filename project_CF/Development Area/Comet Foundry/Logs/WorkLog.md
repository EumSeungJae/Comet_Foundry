### 검증

- `dotnet build project_CF.sln`은 완료됐지만, 현재 솔루션에 Unity C# 프로젝트가 연결되어 있지 않아 실질적인 스크립트 컴파일 검증은 되지 않았다.
- 보이는 Unity Hub 에디터 경로에서 Unity `6000.3.19f1`을 찾을 수 없어 Unity 배치 컴파일은 실행하지 못했다.
- 이 셸에서는 `git`이 PATH에 잡혀 있지 않았다.

### 메모

- 이 프로젝트는 Abyss Tide와 별개의 새로운 Comet Foundry 작업환경이다.
- 현재 프레임워크는 씬, 프리팹, UI보다 순수 시뮬레이션 상태를 먼저 잡는 방향으로 구성했다.

### 혜성 내부 타일 배치 방향 반영

- 혜성 내부 개발 화면은 XCOM 방식의 사각 타일 배치도로 사용하기로 했다.
- `CometGrid`, `CometTile`, `PlacementSystem`, `RailSegment`를 추가했다.
- `FacilityDefinition`에 시설 발자국 크기 `FootprintSize`를 추가했다.
- `FacilityInstance`에 배치 기준 좌표 `Anchor`를 추가했다.
- `CometState`가 자체 내부 그리드와 레일 목록을 가지도록 확장했다.
- 시설과 레일이 같은 타일을 동시에 점유하지 못하도록 기본 배치 검사를 추가했다.

### 건설 테스트 씬 추가

- `Assets/CometFoundry/Scenes/ConstructionTestScene.unity`를 추가했다.
- `ConstructionTestSceneController`를 추가했다.
- 플레이 모드에서 12x8 혜성 내부 테스트 보드를 자동 생성한다.
- 2x2 테스트 구조물을 런타임 임시 `FacilityDefinition`으로 만든다.
- 좌클릭으로 구조물 또는 레일을 배치할 수 있다.
- `Tab`으로 구조물/레일 모드를 전환한다.
- `R`로 테스트 보드를 초기화한다.
- HUD는 `OnGUI` 기반으로 임시 구현했다.
- 프로젝트 입력 설정에 맞춰 새 Input System을 사용하도록 처리했다.

### 마켓/로지스틱 시스템 임시 비활성화

- 건설 테스트 흐름을 먼저 살리기 위해 `MarketSystem`과 `LogisticsSystem`을 조건부 컴파일 뒤로 뺐다.
- `CometFoundryGame`에서 두 시스템 인스턴스 노출을 제거했다.
- 나중에 다시 켤 때는 `COMET_FOUNDRY_ENABLE_MARKET`, `COMET_FOUNDRY_ENABLE_LOGISTICS` 심볼을 사용한다.

### 컨베이어 레일 드래그 건설 추가

- 레일 모드에서 좌클릭 드래그로 경로 프리뷰를 만들도록 변경했다.
- `Enter` 또는 HUD의 `레일 확정` 버튼으로 프리뷰 경로를 실제 레일로 건설한다.
- `Esc` 또는 HUD의 `취소` 버튼으로 프리뷰를 버린다.
- 배치 불가능한 경로는 붉은 프리뷰로 표시하고 확정할 수 없게 했다.
- `PlacementSystem`에 경로 검증과 경로 일괄 배치 기능을 추가했다.

### 컨베이어 경로 입력 방식 변경

- 레일 경로가 자동 생성되지 않도록 바꿨다.
- 마우스가 실제로 지나간 인접 타일만 프리뷰 경로에 추가한다.
- 비인접 타일로 건너뛴 경우 자동 보정하지 않고 연결하지 않는다.
- 이미 지나간 타일로 되돌아가면 그 지점 이후의 프리뷰 경로를 제거한다.

### 컨베이어 방향 검증 추가

- 확정된 레일 경로를 `RailLine`으로 저장하도록 했다.
- 레일 확정 시 방향 테스트용 구체를 생성한다.
- 구체는 드래그한 타일 순서대로 시작점에서 끝점 방향으로 반복 이동한다.
- HUD에 방향 테스트 구체 수를 표시한다.

### 컨베이어 라인 간 전달 추가

- 테스트 구체가 레일 라인의 끝에 도착했을 때 다른 레일 라인의 시작점이 맞닿아 있으면 다음 라인으로 이동하도록 했다.
- HUD에 컨베이어 전달 횟수를 표시한다.
- `RailLine`에 `Start`, `End`, `SegmentCount` 속성을 추가했다.

### 컨베이어에서 건물 입고 테스트 추가

- 레일 라인의 끝이 건물 타일과 맞닿아 있으면 테스트 구체를 건물에 입고하도록 했다.
- 입고된 구체 수를 시설별로 기록한다.
- 테스트 구조물은 입고 3개 미만이면 빨간색, 3개 이상이면 파란색으로 표시한다.
- HUD에 건물 입고 횟수를 표시한다.

### 건물 생산 구체 배출 테스트 추가

- 건물이 입고 3개를 달성해 파란색 상태가 되면 생산 배출 조건을 검사한다.
- 건물 하단 라인에 컨베이어 시작점이 있으면 생산 구체를 해당 컨베이어에 올린다.
- 생산 구체는 초록색으로 표시한다.
- 같은 건물과 같은 컨베이어 라인 조합에서는 중복 생산 구체를 한 번만 만든다.
- HUD에 건물 생산 횟수를 표시한다.

### 건물 스택 소비와 컨베이어 대기 규칙 추가

- 건물이 생산할 때 내부 스택 3개를 소비하도록 변경했다.
- 건물 내부 스택이 이미 3개 이상이면 컨베이어 끝의 입력 구체는 건물에 들어가지 않고 대기한다.
- 대기 중인 구체는 건물 스택이 소비되어 여유가 생기면 다시 입고된다.
- 건물 하단 출구와 연결된 컨베이어 시작점에는 자연 테스트 구체를 생성하지 않는다.
- 출력 컨베이어에는 건물이 생산한 초록색 구체만 올라가도록 정리했다.

### 혜성 등급과 시드코드 규칙 추가

- 혜성마다 8자리 구조화 시드코드를 만들도록 했다.
- 1번째 자리는 건설 가능 타일 활성화 비율 코드이다.
- 2번째 자리는 혜성 내부 보드 크기 코드이다.
- 3번째 자리는 0~3 사이의 자원 종류 수이다.
- 4~6번째 자리는 혜성에 부여되는 자원 종류 코드이다.
- 7~8번째 자리는 A-0 관문 기준 거리 코드이다.
- 거리 코드 `A0`은 A-0 관문 좌표로 예약하고 혜성 생성에서는 제외한다.
- 새 혜성의 거리 코드가 기존 소유 혜성과 같으면 다시 산출해 다른 거리 코드를 부여한다.
- 숫자 코드 1 차이는 5분 거리, 알파벳 코드 1 차이는 1시간 거리로 해석한다.
- 활성화 코드 `S`는 건설 가능 타일 100%, `A`~`F`는 90%, 80%, 70%, 60%, 50%, 40%를 가진다.
- 사이즈 코드 `S`는 16x16 내부 보드, `A`는 14x14이며 `B`부터 `F`까지 1씩 줄어든다.
- 비활성 타일은 `Void` 지형으로 지정해 건설 불가능하게 처리한다.
- 월드 HUD에 시드코드, 활성화/크기 등급, 건설 가능 비율, 거리 코드를 표시한다.
- `CometGeneratorTests`를 추가해 등급별 크기, 활성화 비율, 시드코드, 실제 활성 타일 수를 검증한다.

### 회사 컨셉과 지구 시장 경제 방향 기록

- `A0` 좌표의 공식 명칭을 A-0 관문으로 정했다.
- A-0 관문 안에서 혜성거래소가 기능한다.
- 혜성거래소는 플레이어 대신 혜성을 찾고 소개하며, 플레이어가 납품한 물건을 지구로 보내 판매하는 회사이다.
- 플레이어는 민간 생활 기업, 상업 우주개발 기업, 군수 기업, 에너지 기업, 연구/첨단 기업 같은 방향으로 회사를 특화할 수 있다.
- 건물 건설에는 돈뿐 아니라 가공품 재료와 완성품 재료가 필요하도록 설계했다.
- 필요한 건설 재료를 전부 자체수급할 수 있으면 건설 비용을 90% 절감하는 방향으로 기록했다.
- 혜성거래소에서 일정 확률로 지구 시장 뉴스와 소식을 받는 구조를 추가했다.
- 뉴스는 미래 이벤트의 확정 알림이 아니라 가능성 신호이며, 플레이어는 이를 보고 선투자할 수 있다.
- 예를 들어 전쟁 분위기 뉴스 후 전쟁이 발발하면 군수품 가치가 상승하고, 평화롭게 끝나면 군수품 가치가 하락한다.
- 지구 이벤트가 제품군별 수요와 시세를 바꾸는 경제 시스템을 GDD에 추가했다.
- 이벤트 예시는 인구 증가, 전쟁, 전염병, 우주개발 붐, 에너지 위기, 재건 사업으로 정리했다.
