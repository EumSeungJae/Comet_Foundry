# 코멧 파운드리 기술 부족 사항 목록

원문 최종 갱신일: 2026-08-26
한글화 작업일: 2026-10-14

이 문서는 작성 당시 프로젝트 상태를 코멧 파운드리 개발 로드맵 및 게임 기획서와 비교하여 확인한 기술 부족 사항을 기록한다. 아래 상태와 검증 결과는 2026-08-26 당시의 기록이며, 현재 구현 상태나 해결 여부를 의미하지 않는다.

## 전체 평가

당시 구현은 기획만 있는 단계를 넘어섰다. 실행용 어셈블리 빌드에 성공했으며, 혜성 생성, 격자 배치, 시설, 컨베이어, 드론 물류, 시장 시세, 거래소 의뢰, 연구, 전력의 시제품 시스템이 존재했다.

핵심 부족 사항은 개별 시스템이 없는 것이 아니라, 시스템들이 하나의 연속적인 플레이 흐름으로 연결되지 않았다는 점이다.

목표 플레이 흐름:

1. 혜성을 발견하거나 선택한다.
2. 채굴 시설과 생산 시설을 배치한다.
3. 매장량이 한정된 자원을 채굴한다.
4. 컨베이어 또는 드론으로 자원을 운반한다.
5. 생산법에 따라 소재와 제품을 가공한다.
6. 재고를 보관하거나 판매하고, 의뢰에 납품한다.
7. 자금과 신뢰도를 얻는다.
8. 연구, 전력, 신규 시설을 통해 사업을 확장한다.

## 누락되었거나 미완성인 기술

### 1. 통합 플레이 흐름

당시 상태: 우선순위가 높은 부족 사항.

- 월드 시제품과 건설 시제품이 서로 다른 장면으로 분리되어 있다.
- 혜성 선택에서 혜성 내부 건설로 이어지는 흐름이 없다.
- 시설 생산, 물류, 경제, 의뢰를 하나의 플레이 흐름으로 경험할 수 없다.
- `CometFoundryGame`은 시장 이벤트, 시장 시세, 의뢰를 진행하지만 시설·자원·물류 시뮬레이션 전체를 조율하지는 않는다.

필요한 작업:

- 월드 지도에서 선택한 혜성의 격자로 전환하는 장면 또는 제어 흐름.
- 월드, 건설, 생산, 물류, 경제가 공유하는 게임 상태.
- 철을 생산·판매하여 다음 시설 건설비를 마련하는 등의 최소 플레이 목표.

### 2. 실제 시설 데이터와 생산법 자산

당시 상태: 우선순위가 높은 부족 사항.

- `FacilityCatalog`에 시설 분류가 있지만 대부분 시제품 정의이다.
- 광석 채굴기와 제련로의 생성 이미지가 있으나 완성된 자산 제작·연결 과정은 없다.
- 생산 단계는 기획되어 있지만 초기 생산 사슬에 사용할 안정적인 데이터가 필요하다.

필요한 작업:

- 자원 자산: 철광석, 구리광석, 얼음, 철, 강철, 프레임, 기계부품, 생활소비재.
- 채굴, 정제, 가공, 조립, 판매 준비에 필요한 생산법 자산.
- 생산법, 전력 소비, 용량, 설치 면적, 투입 재료, 생산물을 연결한 시설 정의.
- 실행 중에만 생성하는 임시 데이터 대신 Unity에서 작성한 `ScriptableObject` 자산.

### 3. 자원 채굴과 고갈

당시 상태: 우선순위가 중상인 부족 사항.

- 매장량이 한정된 자원과 기본 재고 기능이 존재한다.
- 자원 노드에서 시설 생산물로 이어지는 전체 채굴 과정이 일반적인 플레이 동작으로 구현되어 있지 않다.

필요한 작업:

- 혜성 매장 자원에 연결된 채굴 시설.
- 채굴 속도, 고갈, 채굴 중단 또는 빈 매장지의 처리.
- 원자재를 시설 재고 또는 인근 물류로 전달하는 규칙.
- 남은 매장량을 보여주는 시각 표시와 디버깅 정보.

### 4. 생산 사슬 실행

당시 상태: 우선순위가 중상인 부족 사항.

- `FacilityInstance`가 생산을 담당하지만 건설 시제품은 단순화된 시험용 물품 로직을 사용한다.
- 실제 생산법 사슬이 주된 플레이 경로로 사용되지 않는다.

필요한 작업:

- 시설의 투입·배출 지점 또는 방향 규칙.
- 생산법 선택 및 가동 중인 생산법 상태.
- 투입 재료 소비, 생산 시간, 생산물 생성, 생산 대기 조건.
- 주 시뮬레이션 흐름에 생산 갱신 처리 통합.
- 여러 시설에 걸친 다단계 생산 사슬 테스트.

### 5. 물류 통합

당시 상태: 우선순위가 중상인 부족 사항.

- 건설 시제품에 컨베이어 경로 배치와 물품 전달 동작이 존재한다.
- 드론 물류와 경로 시스템에 대한 테스트가 있다.
- 플레이 가능한 장면에서 실제 재고와 생산 시설에 완전히 연결되지 않았다.

필요한 작업:

- 실제 자원 스택을 운반하는 컨베이어 구간.
- 실제 재고 자원을 사용하는 시설 투입·배출 연동.
- 시설 수요에 연결된 드론 격납고 배정과 운반 요청.
- 실제 플레이에서의 경로 우선순위, 막힌 경로 처리, 창고·거래소 배송.
- 화물, 드론, 경로 상태의 시각 표시.

### 6. 보관과 창고 동작

당시 상태: 우선순위가 중간인 부족 사항.

- 재고 시스템은 보관 용량과 스택 제한을 지원한다.
- 창고 시설 분류가 존재한다.
- 전용 창고의 플레이 기능은 미완성이다.

필요한 작업:

- 창고의 입고·출고 규칙.
- 보관 목적지로 물자를 보내는 동작.
- 용량 초과 및 보관 공간 부족으로 인한 상위 생산·물류 대기 처리.
- 플레이어가 창고 재고를 확인하는 화면.

### 7. 경제·시장·의뢰 납품 통합

당시 상태: 우선순위가 중간인 부족 사항.

- 시장 시세, 시장 이벤트, 신뢰도, 의뢰 시스템과 테스트가 존재한다.
- 실제 생산물과 연결되어 처음부터 끝까지 진행하는 플레이 흐름은 미완성이다.

필요한 작업:

- 판매 터미널 또는 거래소 터미널 동작.
- 실제 물품을 거래소 의뢰에 납품하는 기능.
- 의뢰 완료 화면과 보상 안내.
- 물품 분류 및 생산 계획과 연결된 시장 수요 분류.
- 자체 생산한 자재를 사용한 건설비 절감.

### 8. 전력망 플레이

당시 상태: 우선순위가 중간인 부족 사항.

- 전력 생산·소비 규칙에 대한 테스트가 있다.
- 시제품 장면에서 전력이 플레이를 제한하는 주요 요소로 작동하지 않는다.

필요한 작업:

- 배치 가능한 발전소 시설.
- 플레이어에게 표시하는 격자 단위 전력 현황.
- 전력이 부족한 시설의 동작.
- 필요할 경우 전력 연결 또는 공급 범위 규칙.

### 9. 연구 해금 흐름

당시 상태: 우선순위가 중간인 부족 사항.

- 연구 정의와 연구 시스템이 존재한다.
- 완성된 연구 계통도 화면과 해금에 따른 시설·콘텐츠 진행이 없다.

필요한 작업:

- 연구 점수 생성 또는 연구소 동작.
- 연구 계통도 데이터.
- 시설, 생산법, 물류 규칙, 효율 개선의 해금 효과.
- 연구 선택 및 완료 화면.

### 10. 플레이어 화면

당시 상태: 실제 플레이 관점에서 우선순위가 높은 부족 사항.

- 시제품 화면은 임시 `OnGUI` 디버깅 패널을 사용한다.
- 정식 플레이에 사용할 현황 표시, 건설 메뉴, 재고·물류·시장·연구 패널이 없다.

필요한 작업:

- 시설 분류별 건설 메뉴.
- 선택한 혜성과 시설의 정보 패널.
- 재고와 자원 수량 표시.
- 생산 상태 및 생산 대기 사유.
- 물류 경로와 화물 상태 화면.
- 시장, 의뢰, 연구 화면.

### 11. 저장과 불러오기

당시 상태: 미구현.

- 개발 로드맵에 저장·불러오기가 있으나 구현되어 있지 않다.

필요한 작업:

- 저장 가능한 형식으로 변환하는 회사 상태.
- 혜성, 격자, 시설, 운송 레일, 재고, 경로, 수송선, 의뢰, 시장 상태, 연구의 저장 데이터.
- 버전을 구분하는 저장 데이터 형식.
- 수동 저장·불러오기와 향후 자동 저장.

### 12. 콘텐츠 제작 과정과 이미지 연결

당시 상태: 초기 단계.

- 생성된 시설 이미지가 일부 존재한다.
- 대부분의 시설, 자원, 효과, 아이콘, 화면 이미지가 일관된 제작·연결 과정에 통합되지 않았다.

필요한 작업:

- 자산 이름과 가져오기 규칙.
- 시설·자원 정의에 연결된 스프라이트 이미지.
- 자원 및 화면 조작용 아이콘.
- 배치 미리보기 이미지와 상태 표시.
- 채굴, 생산, 전달, 판매 효과.

### 13. 장면과 플레이 테스트 검증

당시 상태: 미완료.

- `dotnet build project_CF.sln` 명령은 통과한다.
- Unity 플레이 모드 동작은 에디터에서 확인해야 한다.
- `dotnet test project_CF.sln` 명령은 성공으로 종료하지만 당시 명령 실행 환경에서 자세한 NUnit 테스트 결과가 출력되지 않는다.

필요한 작업:

- `WorldPrototypeScene`과 `ConstructionTestScene`의 Unity 에디터 플레이 테스트 점검표.
- 결과를 확인할 수 있는 Unity 편집 모드·플레이 모드 자동 테스트.
- 전체 플레이 흐름을 빠르게 검증하는 기본 동작 시험 장면.
- 생성된 `.csproj` 파일에 신규 스크립트가 모두 포함되는지 정기 확인.

## 권장 다음 기술 개발 목표

핵심 플레이를 처음부터 끝까지 경험할 수 있는 장면 하나를 구현한다.

1. 혜성 하나를 생성하거나 선택한다.
2. 광석 채굴기, 제련로, 창고, 거래소 터미널을 배치한다.
3. 매장량이 한정된 자원에서 철광석을 채굴한다.
4. 광석을 제련로로 운반한다.
5. 철 또는 강철을 생산한다.
6. 생산물을 창고 또는 거래소 터미널로 운반한다.
7. 물품을 판매하거나 거래소 의뢰 하나를 완료한다.
8. 얻은 자금으로 다음 시설을 건설한다.

이 목표를 달성하면 개별 시스템 시제품에서 실제로 플레이 가능한 핵심 게임 흐름으로 발전할 수 있다.
