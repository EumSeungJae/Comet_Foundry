# 결정 기록

## 2026-10-08 — 첫 플레이 데이터

- 사용자 위임에 따라 초기 16종 자원·16종 레시피·9종 건설 시설의 비용과 시간을 구성했다.
- 건물 주색은 흰색, 보조색은 주황색. 생산 건물 클릭 시 팝업에서 생산품과 비용·시간·완성품을 확인하고 설정한다.
- 기존 프레임워크를 재사용하는 별도 플레이 장면을 추가했다. 시작은 고정 혜성 하나이며 첫 목표는 산업장비 5스택 판매다.
- 생산 재료와 솔라는 완성 시 차감한다. 공간이 부족하면 재료를 보존하고 대기한다. 같은 생산품 재선택은 진행도를 유지한다.
- 로컬 단일 저장 슬롯을 사용하며 실제 경과 시간에 따른 오프라인 생산은 계산하지 않는다.
- 초기 드론 운송은 한 건씩 자동 배정하고, 가격은 기준가로 고정한다. 월드·연구·시세·화물선은 후속 통합 대상으로 남겼다.

## 2026-08-05

### 회사를 최상위 소유자로 둔다

결정:

`CompanyState`를 최상위 런타임 상태로 둔다. 혜성, 화물선, 노선, 시설은 회사 자산이다.

이유:

게임 컨셉상 플레이어는 개별 광산, 공장, 운송선이 아니라 우주 산업 회사를 운영한다.

### 정적 데이터와 런타임 상태를 분리한다

결정:

조정 가능한 정적 데이터는 `CometFoundry.Data` 아래 ScriptableObject로 둔다. 실행 중 변하는 상태는 `CometFoundry.Simulation` 아래에 둔다.

이유:

자원, 레시피, 시설, 화물선, 연구, 생성 프로필은 Unity 에디터에서 조정해야 한다. 재고, 생산 진행도, 고갈된 매장량, 노선 상태, 자금은 저장 가능한 런타임 상태로 관리해야 한다.

### 혜성은 사라지지 않는다

결정:

`ResourceDeposit`은 고갈될 수 있지만, `CometState`에는 수명이나 파괴 규칙을 두지 않는다.

이유:

채굴이 끝난 혜성도 회사 부동산, 물류 공간, 공장 부지, 연구 거점, 허브로 계속 활용되어야 하기 때문이다.

### 물류는 수동 명령이 아니라 규칙으로 다룬다

결정:

`TransportRoute`는 `AutomationRule`을 가진다. 화물선은 반복적인 수동 명령을 기다리는 대신 노선 규칙을 평가한다.

이유:

핵심 재미는 산업망 설계다. 플레이어는 조건, 우선순위, 노선을 설계해야 한다.

### 혜성 내부는 사각 타일 배치도로 개발한다

결정:

혜성 내부 개발 화면은 XCOM 방식의 사각 타일 보드로 구성한다. 플레이어는 그 위에 건물과 물자 이송 레일을 배치한다.

이유:

혜성은 월드맵에서는 하나의 우주 자산이지만, 실제 개발 단계에서는 공장 배치와 내부 물류 흐름을 읽기 쉬워야 한다. 사각 타일은 건설 가능 여부, 시설 크기, 레일 연결, 병목, 확장 계획을 명확하게 표현하기 좋다.
